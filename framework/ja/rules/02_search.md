# 02 — 求人検索

> 日本語訳です。エージェントが従う正本は `framework/rules/02_search.md`（英語）です。

## 検索前の確認

1. 条件が `confirmed`、またはユーザーが明示的に検索を求めた（その場合は要約に「条件確定前に検索」と記録）。
2. インデックスを確認済み（03 参照）：`positions.tsv`、`companies.tsv`、`search_runs.tsv` の直近の行。
3. `workspace/shared/analysis/preference_model.md` の「要検証」「検索のヒント」を読んだ。
4. **勤務エリアが不明なら質問する。** 地域を仮定しない。situation に引っ越し予定があれば、現住所と転居先のどちらを基準にするか確認する。

## 件数

- 既定：**1セッションあたり 5〜10 件を推薦**。閲覧数に制限はないが、すべて `search_runs.tsv` に記録する。
- `requirements.md` の「検索設定」があればそちらを優先。
- 多くて雑より、少なくて的確な方がよい。

## 手法を多様にする

1セッションで**2種類以上の手法**を使い、最近あまり使っていない手法・ソースを優先する（`search_runs.tsv` を確認）。

| コード | 手法 | 内容 |
|---|---|---|
| M1 | 求人サイトのキーワード検索 | 職種 × スキル × エリア |
| M2 | スキル起点の逆引き | ユーザーのスキルを必要とする企業を探し、採用ページを確認 |
| M3 | 企業探索 | 業界地図、上場企業、資金調達ニュース → 採用ページ |
| M4 | ATS 直接検索 | 公開 ATS ページ（HERP、Greenhouse、Lever など）を `site:` で検索 |
| M5 | 類似展開 | 高評価の求人から、競合・同業・同じ投資家の企業へ |
| M6 | コミュニティ・イベント | 企業ブログ、イベント協賛企業、業界コミュニティ |
| M7 | 英語環境の求人サイト | 日本の英語環境の求人に特化したサイト |
| M8 | 探索（条件を緩める） | 必須でない条件を1つ意図的に緩め、本当の許容範囲を探る。件数上限はユーザー設定（既定 1〜2 件）。必ず「探索」と明記し、緩めた条件を書く |

## ソースの選び方

- `framework/sources/job_sources_japan.md` の **Tier A / B のみ**を使い、Tier A を中心にする。それ以外はユーザーに確認してから。
- `workspace/profile/used_sites.md` を読み、各サイトへのユーザーの評価を尊重する。
- `search_runs.tsv` を見て、毎回同じソースばかり使わない。

## 信頼性チェック（すべての候補に実施）

以下は除外するか、カードに懸念として明記する：
- **匿名求人**（企業名非公開、紹介会社による「大手メーカー」など）→ `requirements.md` のユーザー設定に従う。未設定なら質問する。
- 掲載日が不明、または3か月以上前 → 企業サイト・ATS で募集中か確認。確認できなければ「有効性不明」と記載。
- 集約サイト（Tier B）の結果 → 元の掲載ページを探し、その URL を使う。
- 非現実的に広い年収レンジ、曖昧な業務内容、煽り文句だけの求人。
- 派遣・SES・客先常駐 → ユーザーの条件が許す場合のみ。
- 知らない小規模企業 → 実在を確認（企業サイト、国税庁 法人番号公表サイト）。

## 絞り込みと評価

1. **必須条件を満たさない → 除外。** `search_runs.tsv` の `excluded` に計上（カード不要）。
2. 重複チェック（03）。既知の求人は、実質的な変更（年収・条件）があって伝える価値がある場合を除き再推薦しない。
3. `companies.tsv` で `avoid` の企業 → 除外。
4. 残りを `preference_model.md` に照らして評価。**推薦理由**と**懸念**を、合わない点も含め正直に書く。
5. 可能な限り募集中か確認する。できなければその旨を書く。

## 出力

- 検索過程（クエリ、見たもの、除外理由）→ `workspace/agents/<agent-id>/searches/YYYY-MM-DD_NN.md`
- 推薦リスト → `workspace/agents/<agent-id>/recommendations/YYYY-MM-DD.md`（テンプレート `framework/templates/agent/recommendation.md`。求人ごとに空の「あなたの感想」欄を入れ、ファイルの場所をユーザーに伝える）
- 推薦する求人 → `workspace/shared/positions/` にカード、`positions.tsv` に1行（03）
- 各検索アクション → `search_runs.tsv` に1行

## 言語

- 求人情報（会社名、職種、業務内容、条件）は**原文のまま**。
- 推薦理由・懸念・分析はユーザーの会話言語で書く。

## 制限

- **`05_privacy_and_safety.md` が最優先。** 要点：
  - **ログインしない。ログイン不要で見られるページのみ使う。** ログイン画面が出たらスキップし、ログに「ログイン必須のためスキップ」と記録。
  - **検索クエリに個人情報を入れない。** 経歴は先に一般的な言葉に抽象化する。
  - フォームは送信しない。
- 各サイトの利用規約を守る。高頻度の大量取得をしない。
- わからない情報（実際の年収、離職率など）は「不明」と書く。決して作らない。
