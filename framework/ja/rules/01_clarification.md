# 01 — 希望条件の整理

> 日本語訳です。エージェントが従う正本は `framework/rules/01_clarification.md`（英語）です。

人は自分が本当に何を求めているか、まだわかっていないことが多い。目的はフォームを埋めることではなく、**実際の判断を左右する条件**と**その優先順位**を見つけること。

## いつ整理するか

- `workspace/shared/requirements_clarified.md` の `status` が `confirmed` でない → 整理する。
- `confirmed` でも、フィードバックと矛盾する、状況が変わった、確認から1か月以上経った → 簡単な見直しを提案（断られてもよい）。
- ユーザーが「もう話し合ったので検索して」と言った → スキップし、セッション要約に記録する。

## 質問の仕方

1. **先に profile / requirements / situation を読む。** すでに答えがある質問はしない。
2. **一度に 2〜4 問まで。** 長いアンケートにしない。
3. まず求人を即座に除外する**必須条件**を確定する。**どれもデフォルトを仮定せず、必ず質問する。**
   - 勤務エリアと通勤・リモートの希望
   - 最低年収、雇用形態（正社員、契約社員、業務委託など）
   - 業務言語（日本語／英語／両方）
   - ビザ（該当する場合）
   - 入社時期（situation のスケジュールや生活費の余力と照合）
4. 次に**好み**を、「X は好きですか」ではなく**トレードオフ質問**で探る：
   - 「年収アップだがフル出社、現年収だがフルリモート、どちら？」
   - 「安定した大企業で古いやり方、変化の大きいスタートアップ、どちら？」
5. 「どちらでも」「わからない」は `undecided` として記録し、あとでフィードバックから推測する（04 参照）。答えを強要しない。
6. **situation を活かす。** 例：引っ越し予定があれば通勤エリアが変わる。生活費の余力は活動期間やリスク許容度に影響する。
7. `requirements.md` の検索設定（推薦件数、匿名求人、探索用の求人）が空欄なら確認する。

## 記録

- 結論は `workspace/shared/requirements_clarified.md` に書く：
  - 各項目のレベル：`hard`（満たさなければ除外）/ `strong` / `nice` / `undecided`
  - 出典：`user-stated` / `inferred`（要確認）/ `inferred→confirmed`
- 必須条件がすべてユーザーに確認されたら `status: confirmed` にし、日付と agent-id を書く。
- 議論の方向性はセッション要約に記録。
- 未回答の質問は `workspace/shared/open_questions.md` へ。
